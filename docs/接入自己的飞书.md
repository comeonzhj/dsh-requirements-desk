# 接入自己的飞书

这个仓库只带虚构数据快照。要连接你自己的飞书多维表，按下面几步做。

## 1. 准备 Base

在飞书里创建一个多维表，表名建议为 `需求池`。字段结构可以直接复用 [fields.example.json](fields.example.json)：

```bash
lark-cli base +base-create \
  --name "需求台" \
  --table-name "需求池" \
  --time-zone Asia/Shanghai \
  --fields "$(cat docs/fields.example.json)" \
  --as user
```

也可以手动建表。页面读取这些中文列名：`需求ID`、`需求标题`、`来源类型`、`来源`、`提出方`、`部门`、`角色`、`客户分层`、`模块`、`需求类型`、`场景`、`痛点`、`原话`、`优先级`、`状态`、`影响人数`、`商业价值`、`战略契合`、`实现成本`、`置信度`、`紧急度`、`标签`、`提交日期`、`补充说明`、`PM 结论`。

## 2. 取 Base Token 和 Table ID

打开 Base，看地址栏：

```text
https://<your-domain>.feishu.cn/base/<base_token>?table=<table_id>&view=<view_id>
```

- `base_token`：`/base/` 后面那一段；
- `table_id`：`?table=` 后面那一段，`tbl` 开头。

## 3. 配置插件

复制 `plugin/data/local-config.example.json` 为 `plugin/data/local-config.json`，填自己的值；这个文件不会进仓库。也可以直接改 `plugin/cordis.patch.yml`：

```yaml
- insert:
    - id: requirements-desk
      name: '@local/requirements-desk'
      config:
        baseToken: "<your-base-token>"
        tableId: "<your-table-id>"
        baseUrl: "https://<your-domain>.feishu.cn/base/<base_token>?table=<table_id>"
        tableName: 需求池
        cliPath: ""
```

`cliPath` 留空时按 PATH 查找 `lark-cli`。如果 DSH 进程找不到它，填 `which lark-cli` 的绝对路径。

不要把 Base Token、App ID、App Secret 提交到公开仓库。这个插件不需要 App Secret。

## 4. 登录与安装

```bash
lark-cli auth login
lark-cli auth status

# 安装本地插件目录
# 在 DSH 的 Plugins > Add plugin 选择 plugin/ 目录
```

装好后打开左侧“需求台”。首次打开显示内置快照；点“同步飞书”读取你的 Base。同步失败会保留快照，并显示原因。

## 5. 验证写回

打开一条需求详情，改优先级或状态，点“保存到飞书”。然后到 Base 里核对对应记录。

写回只允许三个字段：`优先级`、`状态`、`PM 结论`。其余字段页面不改。

## 6. 常见问题

**同步报 `unsafe output path`**：`lark-cli` 只允许把 `--output` 写到当前目录、`/tmp` 或 `~/files`。Host 已用 `/tmp`，如果自定义了临时目录，改回这三个位置。

**同步报权限错误**：`lark-cli auth status` 看用户身份是否有 `base:record:read`，以及当前账号是否能打开这个 Base。

**页面没有“需求台”入口**：刷新 DSH 或重启应用；再检查 Plugins 里 `@local/requirements-desk` 是否 enabled。

**只想看界面，不接数据**：不配置 Base 也能用，页面会读 22 条快照。同步和写回会提示缺少配置。
