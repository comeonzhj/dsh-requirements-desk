## 3. 示例数据覆盖

22 条需求覆盖三条来源线：

- **B 端企业**：客服工单、销售转述、客户成功回访（恒锐制造、中远数科、悦享电商、瑞和证券、嘉禾地产、华澜集团、明诚财务、远行咨询等）。
- **C 端用户**：应用市场评价、C 端表单、用户访谈、社区反馈（4K 字体、冷启动、深色主题、微信文件导入、Webhook 等）。
- **内部同事**：产品、设计、研发、市场、客服、安全合规、客户成功（团队技能包、PPT 模板、PRD 模板、设计组件、工单导出、周报等）。

数据刻意保留了一些“不完美”：

- 有些需求证据强但成本高（知识库、审计）；
- 有些需求影响大但置信度低（微信文件导入）；
- 有些需求是内部效率快赢（工单导出、周报）；
- 有些需求已上线/已搁置，用于验证状态筛选与历史视角。

## 4. 创建与写入命令（可复现）

```bash
# 1) 创建 Base + 首表 + 字段
lark-cli base +base-create \
  --name "WorkBuddy 需求台 · Demo" \
  --table-name "需求池" \
  --time-zone Asia/Shanghai \
  --fields "$(cat .build/fields.json)" \
  --as user

# 2) 批量写入 22 条记录
lark-cli base +record-batch-create \
  --base-token "$BASE_TOKEN" \
  --table-id "$TABLE_ID" \
  --json @.build/records.json \
  --as user

# 3) 导出 NDJSON（生成页面内置快照）
lark-cli base +record-list \
  --base-token "$BASE_TOKEN" \
  --table-id "$TABLE_ID" \
  --limit 200 \
  --format ndjson \
  --output records-export.ndjson \
  --as user
```

> `lark-cli` 的 `--output` 只允许当前目录、`/tmp` 或 `~/files`。Host 侧同步使用 `/tmp`，避免沙箱路径限制。

## 5. 页面数据链路

```
Feishu Bitable
   ↑  lark-cli base +record-list（用户身份）
   │
Host 插件 server.mjs
   ├─ GET  /api/requirements-desk/state   → 归一化记录 + 数据源元信息
   ├─ POST /api/requirements-desk/sync    → 读取最新记录，写入 data/requirements.cache.json
   └─ POST /api/requirements-desk/update  → 字段白名单写回 Base
   │
Client 插件 client.js
   └─ 需求池 / 洞察 / 评审 / PRD / 场景库
```

### 字段白名单

写回只允许三个字段，避免页面误改 schema 或关键数据：

- `优先级` → `P0/P1/P2/P3`
- `状态` → 六个状态值之一（长度上限 20）
- `PM 结论` → 文本，截断 2000 字符

`record_id` 用 `^rec[a-zA-Z0-9]+$` 校验；不合法直接拒绝。

### 失败策略

- **同步失败**：页面保留内置快照/上次缓存，toast 给出具体错误；不会把空数据覆盖到页面。
- **写回失败**：toast 显示错误；页面本地不假装成功。
- **CLI 不可用**：数据桥仍能读快照；同步按钮会提示检查 `lark-cli` 登录态。

## 6. 关于 App ID / App Secret

本插件不需要 App Secret。

`lark-cli` 以当前用户身份登录，已经具备 Base 读写权限；Base 也是用户云空间里的普通资源，链接可以直接打开。

如果要把数据源改成“应用身份 + OpenAPI 直连”：

1. 把 App 加为 Base 协作者，或让 App 拥有 Base；
2. 在 Host 侧用 `tenant_access_token` 调 Bitable OpenAPI；
3. Secret 放 DSH credentials 或 Host 环境变量，不进 `client.js`、仓库或截图。

公开仓库里不要提交 `.env`、Base Token、App ID 或 App Secret。本仓库只带虚构数据快照。

## 7. 已知限制

- 依赖本机 `lark-cli` 登录态；token 过期时需要 `lark-cli auth login`。
- 字段名是中文硬编码映射；改字段名需要同步改 `server.mjs` 的 `normalizeRow`。
- 单次同步上限 200 条（Demo 足够；生产应分页）。
- 没有实时推送；需要手动点「同步飞书」。
- 页面写回是“单条更新”，没有批量操作/撤销。
- Base 的权限、字段选项变更可能影响写回；生产应加 schema 校验和迁移提示。
