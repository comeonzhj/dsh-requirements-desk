# WorkBuddy 工作台 → DSH 插件页：可迁移能力与实现清单

> 结论先行：WorkBuddy 静态工作台最有价值的不是「静态页」，而是 **“页面里的业务对象 → 用户确认 → 作为上下文进入 Agent 工作模式”** 这条链路。DSH 没有 `data-wb-task` / `fillItem` 这套 DOM 契约，但它有更完整的对应物：**Client Slot 页面 + `uiWorkspace.startSession({ prompt })` + Agent Preset + Host Tool/Skill + 主题与 Locale 服务**。这条链路可以迁移，而且可以做得比原方案更安全（密钥留在 Host、上下文可追溯、工作模式可绑定）。

本文基于 WorkBuddy 的 Buddy 应用接入文档（网页资源包、三触点、JSSDK）以及本机 DSH 0.2.2-rc.2 的 Slot / Service 实际注册情况整理。

---

## 1. 能力拆解与迁移映射

| # | WorkBuddy 能力 | 原实现机制 | DSH 对应能力 | 迁移结论 | 实现要点 |
|---|---|---|---|---|---|
| 1 | 静态工作台承载 | zip 包 + `manifest.json` + `buddy-app://` + 允许来源 `allowedOrigins` | Client 插件页：`main` slot + `sidebar.panellist` 入口；React 组件直接渲染，无 iframe | **可迁移，形态改变** | 不再需要 zip/manifest 的页面清单；改为 DSH bundle 的 `dsh.client` + `main` / `sidebar.panellist` 注册 |
| 2 | 触点一：单条加入输入框 | 元素打 `data-wb-task`，页面按钮调 `window.wbTask.fillItem(selector)`；宿主读 title/content 填入输入框，不自动发送 | `ctx.get('uiWorkspace').startSession(workspaceId, { prompt, whenDraftExists: 'replace' })`：在目标工作区新开会话并把内容填入输入框，仍需用户确认发送。也可用 `ctx.sessions.create()` + `session.prompt()` 直接发（语义不同） | **可迁移，语义最接近** | 页面自己维护数据对象，不依赖 DOM 属性；发送前用「工作包」弹窗让 PM 预览/编辑 prompt；按需求 ID 生成可追溯引用 |
| 3 | 触点二：多选 + 宿主底部面板 | 页面写 `data-wb-task-item` + `data-wb-task-check`，宿主注入 Shadow DOM 底部面板，提交后统一清空 checkbox | 页面自己实现多选、底部操作条、全选/清空；DSH 不注入宿主面板 | **可迁移，UI 归页面** | 状态用 React `Set`；底部条放「发起评审 / 交给 Agent 写 PRD / 组装工作包」；提供「已选 N 条」与来源摘要 |
| 4 | 触点三：划词松手菜单 | preload 全局监听 `mouseup`，在落点注入 Shadow DOM 菜单；输入框内不接管 | DSH 对话区有 `conversation.chat.text-interaction`（引用）等文本交互；插件页内没有等价的宿主级划词契约 | **部分可迁移** | 如确实需要，页面自己监听选区并渲染菜单；或者把「引用原话」做成详情抽屉的显式按钮，减少与宿主交互冲突 |
| 5 | 属性契约与文案 | `data-wb-task-title/content/url/label`、`meta wb-task-*`、24 字符上限、空白折叠、条目级覆盖 | 用 TypeScript/JS 数据模型 + Locale 字典 + 页面级/条目级配置；无 DOM 契约 | **可迁移，且更清晰** | 字段用显式 schema（如 `title/summary/evidence/sourceUrl`）；文案走 `ctx.locale.register`；长度限制在 prompt builder 里统一处理 |
| 6 | 内容进入输入框的格式 | 一次提交一个胶囊；N 条标题合并为「首条标题 等 N 条」；正文按 `【标题】正文` 拼接；单条 4000、总 16000 字符 | `startSession({ prompt })` 直接接收字符串；可自由组织 Markdown | **可迁移，格式可升级** | 建议格式：`## 需求材料` + 每条 `### ID 标题` + `- 来源/角色/影响/评分` + `- 原话`；超过长度按条截断并标注 |
| 7 | URL 不进入 prompt | `data-wb-task-url` 只供下游识别 | 同样应默认排除外部 URL，只保留需求 ID / Base record ID | **应保留的设计** | 在 prompt builder 中区分 `sourceUrl`（仅页面展示）与 `evidence`（进入 prompt） |
| 8 | 主题与样式隔离 | 宿主 UI 在 `mode:'closed'` Shadow DOM，`:host{all:initial}`，跟随 Buddy 明暗主题 | DSH 页面直接用 `--dsw-alias-*` 主题 token；插件 CSS 加前缀；宿主自动切换明暗 | **可迁移，更简单** | 只使用 14 个公开 token（bg/label/border/brand/state/sidebar）；不要写死背景色；用 `color-mix` 做层次 |
| 9 | 动态内容自动生效 | `MutationObserver` + 200ms 节流重新扫描 | React 状态驱动；数据源变化通过 fetch/sync 更新；不需要 DOM 扫描 | **不需要迁移** | 列表用 `key` 稳定；同步后整体替换数据；选择集按 ID 保留 |
| 10 | 页面 fetch 与来源白名单 | preload 注入的 `fetch` 策略、`__wbStaticNetPolicy`、`BUDDY_STATIC_FETCH_DENIED` | Host 插件注册 `/api/requirements-desk/*` 路由；浏览器同源 fetch；密钥/CLI 只在 Host | **可迁移，安全性更好** | 浏览器只拿归一化数据；写操作在 Host 做字段白名单；不要把 App Secret 放前端 |
| 11 | `wb.account.profile` / `wb.login` | 宿主账号与应用授权 | DSH 本身已有登录与 Profile；插件页不需要二次登录；需要用户身份时走 Host `sessions` / 通讯录工具 | **可迁移，通常不需要** | 页面头部显示数据源即可；不要自建登录态 |
| 12 | `wb.config.get('theme'/'language')`、`wb.on/off` | 读宿主主题/语言，订阅变化 | Client `ctx.theme` / `ctx.locale` 服务；`ctx.locale.subscribe()`；CSS token 自动跟随 | **可迁移** | 本 Demo 用 `ctx.locale.register/bind` + `subscribe`；主题只靠 token |
| 13 | `wb.fillMessage(content, mode, scene)` | 填入输入框，可带 `mode` / `scene` | `uiWorkspace.startSession({ prompt, agentPreset })`；`mode` 映射为 Agent Preset，`scene` 映射为页面工作模式/提示词模板 | **可迁移，需拆分概念** | `mode` = Agent Preset（会话级能力/工具/提示词）；`scene` = 页面 Playbook（分析/评审/PRD/测评）；不要把两者混成一个字符串 |
| 14 | `wb.sendMessage(content, mode, scene)` | 直接发送 | `ctx.sessions.create()` 后 `session.prompt(content, 'queue')`；或 Host `sessionController.prompt()` | **可迁移，但建议保留确认** | PM 场景不建议静默自动发送；用 draft 语义更符合“先看上下文再发” |
| 15 | `wb.skills.installed`（示例中被拒绝） | 查询已安装技能 | Host `skills` 服务 / `agentPresets.serviceFor(agent,'skills')`；或页面通过 Host 路由暴露技能目录 | **可迁移** | 未授权能力应显式显示「不可用」，不要假装成功；Demo 中 Skills 中台标为「示例接入」 |
| 16 | Desktop 专属 preload / Web iframe 不支持 | Electron `<webview>` preload 与页面共享 DOM；Web 跨域 iframe 无法注入 | DSH 插件页本身运行在 Web GUI（Electron 与浏览器同构），无 preload 依赖 | **可迁移，平台限制消失** | 不再需要“桌面端专属”分支；用 Client 插件即可 |
| 17 | 打包、manifest、资源、体积限制 | zip ≤20MB、≤256 成员、单文件 ≤20MB、声明总解压 ≤50MB；manifest 只解压声明文件 | DSH bundle：`package.json` + `dsh.bundle.patch` + `dsh.client`；`files` 列出运行时文件；本地目录安装 | **可迁移，规则不同** | 不需要 zip；`plugin_manager install_bundle` 或 Plugins > Add plugin；图标/详情/多语言是插件元数据 |
| 18 | 胶囊（chip）交互 | 一个提交一个胶囊，N 条合并文案 | DSH 输入框没有公开的 chip 注入 API；prompt 是纯文本 | **不可 1:1** | 页面内自绘“已选上下文” chips；发送后用 Markdown 标题保持可读性 |

## 2. 三个触点在 DSH 中的推荐实现

### 触点一：单条“加入分析”

原方案：

```html
<div id="item-1" data-wb-task data-wb-task-title="…" data-wb-task-content="…">
  <button onclick="wbTask.fillItem('#item-1')">加入待办</button>
</div>
```

DSH 推荐：

```js
// 页面里的业务对象，不依赖 DOM 属性
const item = { id: 'WB-2026-006', title: '…', evidence: '…' }

// 用户点击“加入分析”后，把 item 放进选择集
setSelected(prev => new Set(prev).add(item.id))

// 用户点击“发送到 Agent”后，打开工作包弹窗
// 确认后：
const workspaceId = /* 当前/最近工作区的 id */
ctx.get('uiWorkspace').startSession(workspaceId, {
  prompt: buildPrompt([item], 'analysis'),
  whenDraftExists: 'replace',
})
```

关键差异：
- **不再从 DOM 读内容**：内容来自数据模型，天然可追溯、可测试。
- **不再自动发送**：`startSession` 的 `prompt` 进入新会话输入框；用户仍可在输入框修改后发送。
- **没有胶囊**：DSH 输入框是纯文本；页面用「已选上下文」chips + prompt 里的 `### ID 标题` 保持语义。

### 触点二：多选 + 底部操作条

原方案依赖宿主的 Shadow DOM 面板；DSH 推荐页面自绘：

```
┌────────────────────────────────────────────────────────────┐
│ 已选 4 条需求   2 条 P0 · 覆盖 2,150 人    清空              │
│ [发起评审] [交给 Agent 写 PRD] [组装工作包]                  │
└────────────────────────────────────────────────────────────┘
```

实现要点：
- 选择集是 `Set<requirementId>`，与筛选结果解耦；切换筛选不会丢选择。
- 底部条只在 `selected.size > 0` 时出现；用 `position: sticky`/flex 固定在内容区底部。
- 所有动作都打开同一个「工作包」弹窗，只切换工作模式，避免四个按钮四套逻辑。
- 提交后清空选择，并 toast 提示“已填入新会话输入框”。

### 触点三：划词/引用

原方案是全局 `mouseup` + 宿主菜单。DSH 的对话区已有引用交互，但插件页没有公开的宿主级划词契约。推荐：

- 详情抽屉里放显式的「复制原话」「引用到分析」按钮；
- 如果一定要划词，页面自己监听 `selectionchange`/`mouseup`，但只在自己的滚动容器内生效，避免与宿主输入框冲突；
- 不把 `location.href` 拼进 prompt（沿用 WorkBuddy 的安全设计）。

## 3. 工作模式：`mode` / `scene` → DSH Preset + Playbook

WorkBuddy 的 `wb.fillMessage({ content, mode, scene })` 把“工作模式”作为一个参数。迁移到 DSH 时建议拆成两层：

| 层 | DSH 对应 | 作用 | 例子 |
|---|---|---|---|
| Agent 能力层 | **Agent Preset** | 决定这个会话有哪些工具、Skill、系统提示词、权限 | `product-manager`、`prototype-designer`、`qa-reviewer` |
| 页面场景层 | **Playbook**（页面内的提示词模板） | 决定这次任务要什么输入、按什么格式输出 | 需求归并、六维评审、PRD、原型、测评、竞品 |

Demo 当前实现的是 **Playbook 层**（`MODES` + `buildPrompt`），发送时使用默认 Preset。要真正绑定 Preset，只需在 `startSession` 里加 `agentPreset`：

```js
ui.startSession(workspaceId, {
  prompt,
  agentPreset: 'product-manager', // 需要先在 profile 中注册该 preset
  whenDraftExists: 'replace',
})
```

建议的 4 个 Preset：

1. `product-manager`：需求分析、PRD、评审；工具含 Base/文档/搜索，权限只读 + 写 PRD 文档。
2. `prototype-designer`：信息架构、线框、组件映射；工具含设计规范检索、画板/HTML 原型。
3. `qa-reviewer`：测评方案、验收标准、回归清单；工具含测试用例库、埋点指标。
4. `research-analyst`：竞品/市场/评价分析；工具含 Web 搜索、评价聚类。

Preset 的落点：**Host bundle / preset 包**，不是页面代码。页面只传 preset id；这样同一个工作台可以被不同团队替换成自己的 preset，而不用改 UI。

## 4. 不可迁移 / 需要重新设计的部分

| 项 | 原因 | 替代方案 |
|---|---|---|
| 向“当前会话”的输入框注入内容 | DSH 公开 Client API 只有 `startSession({ prompt })` 的 draft 语义；没有 fill-current-composer 的公开契约 | 新开会话 + draft；或 Host 侧 `sessionController.prompt()` 直接排队（会自动进入 Agent，需用户明确接受） |
| 宿主注入的多选底部面板 / 划词菜单 | DSH 不提供 WorkBuddy 那种 preload UI 注入契约 | 页面自绘；或做成 `conversation.composer.dock` 的常驻入口（不同交互） |
| 一次提交的“胶囊” | DSH 输入框没有公开 chip API | 页面 chips + prompt 结构化文本 |
| `data-wb-task-bound` 幂等标记 | React 不需要 DOM 标记 | 稳定 `key` + `Set` 选择集 |
| 任意跨域页面 fetch + allowedOrigins | 插件页不直接持有第三方密钥 | Host 路由代理；密钥进 DSH credentials / 环境变量 |
| 静态 zip 的热更新 | DSH bundle 是包级安装 | 本地目录安装 + 重新加载；客户端 HMR 仅在 `pnpm run dev:web` 时自动重建 |

## 7. 一句话总结

WorkBuddy 的工作台接入契约是 **“HTML 标识 + preload 注入 + 宿主填输入框”**；DSH 的对应契约是 **“Client Slot 页面 + 公开 Service/Remote + 新会话 draft + Preset”**。前者胜在接入成本低、三触点开箱即用；后者胜在类型安全、密钥隔离、可组合、跨平台。**把“勾选 → 工作包 → 填入输入框 → 用户确认 → Agent 执行”这条主链路迁移过来，其余 UI 细节按 DSH 的页面规范重做，是可行且更合适的路线。**
