# 需求台

把飞书多维表里的多来源需求，变成产品团队可筛选、可评审、可生成 PRD 并交给 Agent 的工作台。

## 它解决什么问题

需求散落在客服工单、销售转述、应用市场评价、C 端表单和内部群里。产品经理通常要：

1. 手动汇总到表格；
2. 凭印象判断优先级；
3. 再从零写 PRD；
4. 把背景复制给 Agent，重新解释一遍。

需求台把这条链路收进一个页面：**证据 → 决策 → 产出 → 交给 Agent**。

## 主要能力

- **需求池**：搜索、筛选、排序、多选；显示来源、部门、模块、影响人数、机会分。
- **洞察**：来源结构、部门声音、机会矩阵、模块聚类、决策信号（快赢/战略/补证据）。
- **评审**：六维 rubric（商业价值、战略契合、影响规模、证据置信、紧急度、成本可控）与评审纪要。
- **PRD 工坊**：按团队模板生成背景、目标、用户、范围、方案、验收、风险，可复制/下载/交给 Agent。
- **场景库**：需求归并、评审、PRD、原型、测评、竞品六个 Playbook；设计规范/开发规范/案例库/Skills 中台为可替换数据源。
- **写回飞书**：详情抽屉里修改优先级、状态、PM 结论，保存到 Base。
- **交给 Agent**：勾选需求 → 选择工作模式与目标工作区 → 预览/编辑上下文 → 打开新会话并把内容填入输入框（仍需用户确认发送）。

## 数据源

默认使用 22 条虚构需求快照，不包含任何飞书 Base Token、App ID 或 App Secret。

连接自己的 Base：把 `baseToken`、`tableId`、`baseUrl` 填进 `cordis.patch.yml`，并让 `lark-cli` 以当前用户登录。

页面首次打开读内置快照；右上角「同步飞书」通过本机 `lark-cli` 读取最新记录。同步失败时保留上次快照并提示原因。

## 使用方式

1. 左侧边栏点击「需求台」。
2. 在需求池筛选/勾选需求。
3. 底部操作条选择「发起评审 / 交给 Agent 写 PRD / 组装工作包」。
4. 在工作包弹窗里确认模式与上下文，点击「打开新会话并填入」。
5. 到新会话输入框确认后发送。
6. 需要记录决策时，打开详情抽屉修改并「保存到飞书」。

## 设计约束

- **不自动发送**：`uiWorkspace.startSession` 只把内容填入新会话输入框；用户仍需确认。
- **不把密钥放前端**：读写都通过 Host 路由；使用 `lark-cli` 用户授权，不使用 App Secret。
- **写回白名单**：只允许优先级、状态、PM 结论三个字段。
- **只用主题 token**：页面跟随 DSH 明暗主题，不写死背景/文字主色。
- **不改宿主**：页面通过 `main` + `sidebar.panellist` 注册，不替换应用根节点。

## 已知限制

- 同步依赖本机 `lark-cli` 登录态；token 过期需重新登录。
- 字段名中文硬编码；改字段名需同步 Host 映射。
- 单次同步上限 200 条；生产需分页。
- 设计规范/开发规范/案例库/Skills 中台目前是示例接入，未真正读取。
- 尚未绑定 Agent Preset；默认使用当前 profile 的默认 preset。
- 当前版本没有浏览器内视觉验收记录；请在 GUI 中确认布局与明暗主题。
- 弹窗有 Esc 关闭与初始焦点，但没有完整焦点陷阱/背景 inert。
